## 三次修复：Gemini 误报「可访问」（检测方法重写）

- 现象：用户实测某节点（US，FDCservers 机房，IPQuality 风险 99）浏览器访问 Gemini 提示「所在国家/地区不支持」，但检测报 ✅解锁。
- 根因：r9 判定过宽——「200+页面标题含 Gemini」或「3xx 到 gemini 域」就判可用。实际上 **Google 对所有地区（包括被风控标记的机房 IP）都返回同款 Gemini 落地页**，标题都含 Gemini；被标记 IP 登录后才弹「not available in your country or region」，匿名请求根本看不到该文案。
- 权威口径（lmc999/RegionRestrictionCheck 的 WebTest_Gemini）：拉 `https://gemini.google.com` 落地页，grep 内嵌应用数据令牌 `45631641,null,true`，有=Yes、无=No；地区码从 `,2,1,200,"XXX"` 提取。
- r10 重写（commit cf519e2）：
  - 可用 = 落地页含令牌 `45631641,null,true`（顺带提取地区码，正则 `[A-Z]{2,3}` 兼容 alpha-2/3）；
  - 不可用 = support.google.com/gemini 重定向、明确不支持文案、或**落地页正常但无令牌**（覆盖 Google 风控标记机房 IP 情形）；
  - 限流 = 429 / /sorry/ / unusual traffic；
  - 移除「标题含 Gemini 即可用」「3xx 到 gemini 域即可用」两条误判规则（Loon 未跟随重定向时改判 unknown）；
  - 详情文案区分「所在国家/地区不支持或 IP 被风控」。
- 校验：node --check 通过；classifyGemini 12 个分支用例全过（含 FP 修复用例「落地页无令牌」）。
- web 测试版同步：SOURCE_URL 指纹 87a4812→cf519e2，poc14→poc15（commit c6edf67）。
- 经验：Google 落地页不能作为解锁信号；匿名 curl 级检测只能依赖内嵌数据令牌这类「响应差异」，登录后才出现的文案匿名请求拿不到。

## 四次修复：可用节点被误判不支持（令牌格式错配）

- 现象：用户实测确认可用的节点也显示 Gemini 不可用；另有些节点完全没有/显示「未确认」Gemini 行。
- 根因（实测 curl 确认）：当前 gemini.google.com 落地页把可用性内嵌为 JSON 键 **`"45631641":true`**；而此前照搬 lmc999 旧 WIZ 数组片段 `45631641,null,true`，页面里根本没有该字符串 → 可用节点令牌匹配失败 → 落到兜底「有 Gemini 标记则判不可用」→ 误报 ❌。地区码字段 `,2,1,200,"USA"` 真实存在（正则有效）。
- 落地页 gzip 不是原因：Loon `$httpClient` 自动解压，request() 未显式设 Accept-Encoding 但无需。
- r11 修复（commit a17b767）：令牌匹配改 `/"45631641"\s*:\s*true/` + 兼容旧 `45631641,null,true`；新增 `"45631641":false` 直接判不可用；可提取地区码。
- 关于「无 Gemini 行」：renderMediaList 对 unknown 行会渲染为「⚪ 未确认：Gemini」（不消失）；完全缺失只可能发生在该出口到 Google 的请求超时/失败（capture 会回退为「请求失败」行）或落地页既无令牌也无 Gemini 文本 → unknown。令牌修正后绝大多数节点应能正常判出。
- 校验：node --check 通过；classifyGemini 12 用例全过（含 `":true`/`":false`/legacy/无令牌兜底/重定向/限流）。
- web 测试版指纹 87a4812→cf519e2→a17b767 已逐次同步；poc 戳 14→15→16。
- 产品经验：本项目 web 测试版把 SOURCE_URL 钉死在固定 commit，导致主脚本每次改动都要手动同步两处入口（已踩 3 次）。后续若想免维护，可改指向 `refs/heads/main`（失去回滚隔离性），待用户决策。

## 五次修复：可用节点仍误判不可用（转义引号击穿正则 + 页脚 help 链接误判）★根因坐实

- 现象：r11 后用户确认可用的节点还是显示 Gemini 不可用。
- 真根因（实测 gemini.google.com 落地页 + 对照 lmc999 源码确认）：
  1. **令牌引号被转义**：页面里可用性标志写成 `\"45631641\":true`（反斜杠转义引号），而 r11 正则 `"45631641"\s*:\s*true` 要求 45631641 前紧跟真实双引号，转义形式 `\"45631641"` 中无 `"45631641"` 子串 → 永远匹配不到 → 掉进兜底「含 gemini 文本就判不可用」→ 误报 ❌。这是 r9~r11 一直没解决的真正原因。
  2. **页脚 help 链接误判**：支持地区页也内嵌 `support.google.com/gemini?p=avatar` 帮助链接，r11 把「正文含 support.google.com/gemini」也判 region-blocked（false positive）。
- lmc999 真实实现：`curl -sL "https://gemini.google.com" -A 桌面ChromeUA`，grep `45631641,null,true`（旧 WIZ 片段，当前页已无，已被 `\"45631641\":true` 取代）；地区码 `,2,1,200,"[A-Z]{3}"`。本仓库据此对齐：用**桌面 Chrome UA**、**无斜杠 URL** `https://gemini.google.com`。
- r12 修复（commit 1dd6b01）：
  - 令牌正则改为 `/45631641[^a-z0-9]*:\s*(true|false)/`（兼容转义引号、旧 WIZ 数组、无引号三种写法）；`:false`→region-blocked，`:true`→available。
  - region 提取正则 `/,2,1,200,.*?"([A-Z]{2,3})"/` → 升级为 `/,2,1,200,\?"([A-Z]{2,3})\"?/`（兼容转义引号地区码；实测真实页地区码用普通引号，已验证 USA）。
  - **移除正文 support.google.com/gemini 误判**：仅在 `3xx 重定向 Location 指向 support.google.com/gemini` 或带 `not_available` 参数时判 region-blocked。
  - 无令牌且无负面信号 → 判 unknown（绝不误判为不可用）。
  - 请求改桌面 Chrome UA + 无斜杠 URL；SCRIPT_VERSION r12。
- 校验：node --check 通过；classifyGemini 10 个用例全过，含「真实支持页(USA直连)→available+USA」「转义引号 true+转义地区」「支持页含 help 链接仍 available」「`:false`→region-blocked」「3xx 重定向→region-blocked」「无令牌→unknown」。根因佐证：旧正则对真实页命中=false，新正则=true。
- web 测试版同步：SOURCE_URL 指纹 a17b767→1dd6b01，poc16→poc17（commit 2c3729b）。

## 六次修复：不可用节点误显示可用（全局功能标志陷阱）★根因坐实

- 现象：r12 后反过来——用户确认不可用的节点（US 数据中心/被风控）显示 Gemini ✅可用。
- 真根因（实测 gemini.google.com 落地页枚举所有候选信号）：页面里 `45631641` 出现为 `\"45631641\":true` 这种**全局功能标志**（提取上下文：`\"45772048\":false,\"45631641\":true,\"45841483\":false,...` 是一组 feature flag  bundle）。**该标志对所有节点（含被风控/地区不支持）都存在**，与可用性无关。r12 的正则 `/45631641[^a-z0-9]*:\s*(true|false)/` 把它的 `:true` 当成可用信号 → 不可用节点也判 ✅。
- 真正可用区分信号：**WIZ 应用数据令牌 `45631641,null,true`**（lmc999 口径）。实测本沙箱（被标记 IP）落地页 WIZ 格式出现 **0 次**，而真实可用节点才会内嵌它。即：可用 = 有 WIZ 令牌；被标记/不支持 = 只有全局 `\"45631641\":true` 功能标志、无 WIZ 令牌。
- r13 修复（commit e7b94d4）：
  - 可用信号唯一改为 WIZ `45631641,null,true`（命中即 available，顺带 `,2,1,200,\?"([A-Z]{2,3})\"?` 提地区码）；
  - 仅当 WIZ 缺失、但存在全局标志 `45631641...:(true|false)`（正则 `/45631641\\?"?:(true|false)/`，兼容转义/非转义引号、true/false）→ 判 region-blocked（IP 被风控/地区不支持）；
  - WIZ `45631641,null,false` → region-blocked；
  - 其余顺序不变（3xx 跳 support、not_available 参数、明确文案、429/sorry、欧盟同意页、兜底 unknown）。
- 校验：node --check 通过；classifyGemini 14 个用例全过，含「真实被标记页(无WIZ)→region-blocked」「WIZ 令牌→available」「全局标志转义/非转义/`:false`→region-blocked」「3xx/参数/文案/429/欧盟/空响应/无信号」。
- web 测试版同步：SOURCE_URL 指纹 1dd6b01→e7b94d4，poc17→poc18（commit 5627a25）。
- 经验沉淀：Gemini 匿名检测，**绝不能用落地页里任何 `45631641:true` 形式的全局功能标志作可用信号**（所有节点都有）；唯一可靠信号是 WIZ 应用数据令牌 `45631641,null,true`。若未来某次用户反馈「可用节点也显示不可用」，优先怀疑 Google 弃用 WIZ 格式（届时需换探测端点或信号）。
